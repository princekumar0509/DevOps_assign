# S3 - Simple Storage Service (Storage)

> Session 18 - Terraform & IaC | Task 2: AWS Services Research

## What is S3?

Amazon Simple Storage Service (S3) is a fully managed **object storage** service. Data is stored as objects inside buckets and accessed over an HTTPS REST API rather than mounted as a file system or block device.

| Property | Detail |
|---|---|
| Data model | Flat key-value store: bucket + key (+ version ID) maps to an object; "folders" are only key prefixes |
| Durability | Designed for 99.999999999% (11 nines) for all current storage classes |
| Scale | Unlimited total storage and number of objects |
| Consistency | Strong read-after-write consistency for PUT and DELETE of objects in all Regions |
| Default security | Buckets and objects are private; Block Public Access on; ACLs disabled; SSE-S3 encryption applied |

S3 offers four bucket types: **general purpose** (the original type, supporting every storage class except Express One Zone), **directory** (S3 Express One Zone low-latency or data-residency workloads), **table** (Apache Iceberg tables for analytics) and **vector** (vector embeddings for similarity search). The rest of this document focuses on general purpose buckets.

## Why it matters for DevOps

S3 is the default home for build artifacts, deployment bundles, logs, backups, static websites and - very relevant to this session - **Terraform remote state**. Its policies, versioning, lifecycle rules and encryption settings are classic infrastructure-as-code concerns: a single misconfigured bucket policy can expose data publicly, while a missing lifecycle rule can quietly grow costs. Managing buckets with Terraform keeps these settings consistent and reviewable.

Terraform remote state stored in S3 with S3-native state locking (Terraform 1.10 and later):

```hcl
terraform {
  backend "s3" {
    bucket       = "my-tf-state-123456789012"
    key          = "session-18/terraform.tfstate"
    region       = "ap-south-1"
    encrypt      = true
    use_lockfile = true
  }
}
```

## Buckets

A **bucket** is a container for objects. It is created in a specific **Region**, and objects never leave that Region unless explicitly copied or replicated. The name and Region cannot be changed after creation.

- **Global namespace** - general purpose bucket names must be unique across all AWS accounts in a partition (`aws`, `aws-cn`, `aws-us-gov`, `aws-eusc`). A deleted name may be re-created by another account, so names should not be relied on for security.
- **Account regional namespace** - optionally, buckets can be created in a namespace reserved for one account, using names of the form `<prefix>-<account-id>-<region>-an`, which no other account can ever claim.
- **Addressing** - virtual-hosted style URL: `https://<bucket>.s3.<region>.amazonaws.com/<key>`.

**Naming rules** (general purpose buckets):

| Rule | Detail |
|---|---|
| Length | 3 to 63 characters |
| Characters | Lowercase letters, numbers, periods (`.`) and hyphens (`-`) only |
| Format | Must begin and end with a letter or number; no two adjacent periods; must not look like an IP address (e.g. `192.168.5.4`) |
| Reserved prefixes | `xn--`, `sthree-`, `amzn-s3-demo-` |
| Reserved suffixes | `-s3alias`, `--ol-s3`, `.mrap`, `--x-s3`, `--table-s3`; `-an` only for account regional namespace buckets |
| Recommendation | Avoid periods (they break virtual-hosted HTTPS certificates and Transfer Acceleration) |

## Objects

An **object** is the unit of storage and consists of:

| Component | Description |
|---|---|
| Key | Unique name within the bucket, up to 1,024 bytes of UTF-8 (e.g. `releases/v1.4.2/app.zip`) |
| Value | The data itself - any sequence of bytes |
| Metadata | System metadata (`Content-Type`, `Last-Modified`, `ETag`, storage class) and user-defined `x-amz-meta-*` pairs (up to 2 KB) |
| Version ID | Generated by S3 when versioning is enabled; `null` otherwise |
| Tags | Up to 10 key-value tags, used for lifecycle filters, access control and cost allocation |
| Access control | Governed by policies (and ACLs only if they are enabled) |

**Object size**: from 0 bytes to **50 TB** (exactly 48.8 TiB = 10,000 parts x 5 GiB). The limit was 5 TB until AWS raised it in December 2025, so older material still quotes 5 TB. A single `PUT` request can upload at most 5 GB.

**Multipart upload** splits a large object into parts that are uploaded independently and in parallel:

```text
CreateMultipartUpload --> UploadPart x N (parallel, retry individual parts) --> CompleteMultipartUpload
                                    (parts 1-10,000, each 5 MiB - 5 GiB; the last part may be smaller)
```

- Recommended from about **100 MB** and required for objects larger than 5 GB; `aws s3 cp` and `aws s3 sync` use it automatically for large files.
- Parts of incomplete uploads are billed until aborted, so a lifecycle rule with `AbortIncompleteMultipartUpload` is a standard safeguard.

## Storage classes

Every object has a storage class. All classes below are designed for 11 nines of durability; they differ in availability, resilience, minimum charges and retrieval behaviour.

| Storage class (API name) | Designed for | Availability | AZs | Min storage duration | Min billable size | Retrieval |
|---|---|---|---|---|---|---|
| S3 Standard (`STANDARD`) | Frequently accessed data (default) | 99.99% | >= 3 | None | None | Milliseconds, no retrieval fee |
| S3 Intelligent-Tiering (`INTELLIGENT_TIERING`) | Unknown or changing access patterns | 99.9% | >= 3 | None | None (objects < 128 KB are not auto-tiered) | Milliseconds (the optional archive tiers require a restore); small monitoring fee per object; no retrieval fees |
| S3 Express One Zone (`EXPRESS_ONEZONE`) | Latency-sensitive workloads in one chosen AZ (directory buckets) | 99.95% | 1 | None | None | Single-digit milliseconds |
| S3 Standard-IA (`STANDARD_IA`) | Infrequently accessed, long-lived data | 99.9% | >= 3 | 30 days | 128 KB | Milliseconds, per-GB retrieval fee |
| S3 One Zone-IA (`ONEZONE_IA`) | Re-creatable infrequent data | 99.5% | 1 | 30 days | 128 KB | Milliseconds, per-GB retrieval fee; lost if the AZ is lost |
| S3 Glacier Instant Retrieval (`GLACIER_IR`) | Archive accessed about once a quarter | 99.9% | >= 3 | 90 days | 128 KB | Milliseconds, per-GB retrieval fee |
| S3 Glacier Flexible Retrieval (`GLACIER`) | Archive accessed about once a year | 99.99% (after restore) | >= 3 | 90 days | 40 KB metadata overhead per object | Restore first: Expedited 1-5 min, Standard 3-5 h, Bulk 5-12 h |
| S3 Glacier Deep Archive (`DEEP_ARCHIVE`) | Long-term retention, compliance | 99.99% (after restore) | >= 3 | 180 days | 40 KB metadata overhead per object | Restore first: Standard within 12 h, Bulk within 48 h |

## Versioning

Versioning keeps multiple variants of an object under the same key, protecting against accidental overwrites and deletes.

| Bucket state | Behaviour |
|---|---|
| Unversioned (default) | Overwrites and deletes are permanent |
| Enabled | Every PUT creates a new version ID; a simple DELETE adds a **delete marker** instead of removing data |
| Suspended | New writes get version ID `null`; existing versions are kept. A bucket can never return to unversioned |

```text
PUT    report.csv               -> version v1 becomes current
PUT    report.csv               -> version v2 becomes current, v1 becomes noncurrent
DELETE report.csv               -> a delete marker becomes current; v2 and v1 are retained
GET    report.csv               -> 404 Not Found (the current version is a delete marker)
GET    report.csv?versionId=v2  -> returns v2; deleting the marker restores v2 as current
```

- Every version is billed, so versioning is normally paired with a noncurrent-version expiration rule.
- Versioning is required for replication (Same-Region and Cross-Region) and S3 Object Lock (WORM retention); MFA Delete can additionally require MFA to permanently delete versions.

## Lifecycle policies

Lifecycle configurations automate **transitions** between storage classes and **expiration** of objects.

Available actions are `Transitions` (move current versions to a cheaper class after N days), `Expiration` (delete current versions; in versioned buckets this adds a delete marker), `NoncurrentVersionTransitions` / `NoncurrentVersionExpiration` (manage old versions), `AbortIncompleteMultipartUpload`, and `ExpiredObjectDeleteMarker` (remove delete markers with no remaining versions).

Rules can be filtered by prefix, object tags and object size. Objects must stay at least 30 days in their current class before moving to Standard-IA or One Zone-IA, and by default objects smaller than 128 KB are not transitioned.

```json
{
  "Rules": [
    {
      "ID": "logs-tiering-and-expiry",
      "Status": "Enabled",
      "Filter": { "Prefix": "logs/" },
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER_IR" },
        { "Days": 180, "StorageClass": "DEEP_ARCHIVE" }
      ],
      "Expiration": { "Days": 365 },
      "NoncurrentVersionExpiration": { "NoncurrentDays": 30 },
      "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
    }
  ]
}
```

## Encryption

| Option | Who manages the key | Notes |
|---|---|---|
| SSE-S3 | Amazon S3 (AES-256) | Applied automatically to all new objects since January 2023; no extra cost |
| SSE-KMS | AWS KMS (AWS managed key `aws/s3` or a customer managed key) | Key policies control use, every use is logged in CloudTrail; KMS request charges apply, reduced by S3 Bucket Keys |
| DSSE-KMS | AWS KMS | Dual-layer server-side encryption for compliance requirements that mandate two independent layers |
| SSE-C | Customer supplies the key with every request | S3 never stores the key; requests must use HTTPS. Since April 2026, SSE-C is disabled by default for new buckets and must be explicitly enabled through the bucket encryption configuration |
| Client-side encryption | Customer, before upload | Data is encrypted before it reaches S3 (e.g. with the Amazon S3 Encryption Client) |

**In transit**: S3 endpoints support HTTPS (TLS). A bucket policy can deny any request where `aws:SecureTransport` is `false`, and the `s3:TlsVersion` condition key can enforce a minimum TLS version.

## Bucket policies

A **bucket policy** is a resource-based IAM policy (maximum 20 KB) attached to a bucket. It must name a `Principal` and is the standard way to grant cross-account access or enforce bucket-wide rules.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyInsecureTransport",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": ["arn:aws:s3:::my-app-artifacts", "arn:aws:s3:::my-app-artifacts/*"],
      "Condition": { "Bool": { "aws:SecureTransport": "false" } }
    },
    {
      "Sid": "AllowAppRoleRead",
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::123456789012:role/app-ec2-role" },
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": ["arn:aws:s3:::my-app-artifacts", "arn:aws:s3:::my-app-artifacts/*"]
    }
  ]
}
```

`s3:ListBucket` applies to the bucket ARN, while object actions such as `s3:GetObject` apply to `bucket/*` - a common source of "Access Denied" errors.

**Block Public Access (BPA)** provides four settings - `BlockPublicAcls`, `IgnorePublicAcls`, `BlockPublicPolicy` and `RestrictPublicBuckets` - that override any policy or ACL granting public access. They can be set at account and bucket level and are all enabled by default on new buckets. For public websites, the recommended pattern keeps BPA on and serves content through Amazon CloudFront with origin access control (OAC).

**ACLs and Object Ownership**: ACLs are a legacy access mechanism. The default Object Ownership setting, **Bucket owner enforced**, disables ACLs so that the bucket owner owns every object and access is controlled only by policies. AWS recommends keeping ACLs disabled except in rare per-object cases.

## Common use cases

- Terraform remote state and CI/CD artifact storage.
- Centralised logs (CloudTrail, VPC Flow Logs, ALB access logs) with lifecycle-based retention.
- Static website and single-page-app hosting behind CloudFront.
- Backup and disaster recovery targets (AWS Backup, database exports, EBS snapshot archives).
- Data lakes and analytics with Athena, EMR, Glue and S3 Tables.
- Media storage and distribution; ML training datasets.

## AWS CLI examples

```bash
# Create a bucket (outside us-east-1 a LocationConstraint is required)
aws s3api create-bucket --bucket my-app-artifacts-123456789012 --region ap-south-1 \
  --create-bucket-configuration LocationConstraint=ap-south-1

# Harden and configure the bucket
aws s3api put-public-access-block --bucket my-app-artifacts-123456789012 \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3api put-bucket-versioning --bucket my-app-artifacts-123456789012 \
  --versioning-configuration Status=Enabled
aws s3api put-bucket-encryption --bucket my-app-artifacts-123456789012 \
  --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"aws:kms"},"BucketKeyEnabled":true}]}'
aws s3api put-bucket-policy --bucket my-app-artifacts-123456789012 --policy file://bucket-policy.json
aws s3api put-bucket-lifecycle-configuration --bucket my-app-artifacts-123456789012 \
  --lifecycle-configuration file://lifecycle.json

# Work with objects
aws s3 cp ./build/app.zip s3://my-app-artifacts-123456789012/releases/v1.4.2/app.zip
aws s3 sync ./site s3://my-app-artifacts-123456789012/site --delete
aws s3 ls s3://my-app-artifacts-123456789012/releases/ --recursive --human-readable
aws s3api list-object-versions --bucket my-app-artifacts-123456789012 --prefix releases/
aws s3 presign s3://my-app-artifacts-123456789012/releases/v1.4.2/app.zip --expires-in 3600
aws s3api get-bucket-policy-status --bucket my-app-artifacts-123456789012
```

## Terraform example

```hcl
terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 6.0" }
  }
}

provider "aws" { region = "ap-south-1" }

resource "aws_s3_bucket" "artifacts" {
  bucket = "my-app-artifacts-123456789012"
}

resource "aws_s3_bucket_public_access_block" "artifacts" {
  bucket                  = aws_s3_bucket.artifacts.id
  block_public_acls       = true
  ignore_public_acls      = true
  block_public_policy     = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_versioning" "artifacts" {
  bucket = aws_s3_bucket.artifacts.id
  versioning_configuration { status = "Enabled" }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "artifacts" {
  bucket = aws_s3_bucket.artifacts.id
  rule {
    apply_server_side_encryption_by_default { sse_algorithm = "aws:kms" } # AWS managed key aws/s3
    bucket_key_enabled = true
  }
}

resource "aws_s3_bucket_lifecycle_configuration" "artifacts" {
  bucket     = aws_s3_bucket.artifacts.id
  depends_on = [aws_s3_bucket_versioning.artifacts]
  rule {
    id     = "logs-tiering-and-expiry"
    status = "Enabled"
    filter { prefix = "logs/" }
    transition {
      days          = 30
      storage_class = "STANDARD_IA"
    }
    expiration { days = 365 }
    noncurrent_version_expiration { noncurrent_days = 30 }
    abort_incomplete_multipart_upload { days_after_initiation = 7 }
  }
}

resource "aws_s3_bucket_policy" "tls_only" {
  bucket = aws_s3_bucket.artifacts.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "DenyInsecureTransport"
      Effect    = "Deny"
      Principal = "*"
      Action    = "s3:*"
      Resource  = [aws_s3_bucket.artifacts.arn, "${aws_s3_bucket.artifacts.arn}/*"]
      Condition = { Bool = { "aws:SecureTransport" = "false" } }
    }]
  })
}
```

Since AWS provider v4, bucket settings are separate resources rather than inline blocks on `aws_s3_bucket`. Object Ownership already defaults to Bucket owner enforced; `aws_s3_bucket_ownership_controls` can pin it explicitly.

## Key takeaways

- S3 stores objects (key + data + metadata + optional version ID) in Regional buckets whose names are globally unique within a partition.
- Objects can be up to 50 TB; multipart upload is recommended from about 100 MB and required above 5 GB.
- Storage classes trade availability, minimum charges and retrieval time for lower storage cost; lifecycle rules move data between them automatically.
- Versioning protects against overwrites and deletes but must be paired with noncurrent-version expiration to control cost.
- Every new object is encrypted (SSE-S3 by default); SSE-KMS adds key-level control and auditing, and TLS can be enforced by bucket policy.
- Block Public Access and disabled ACLs (Bucket owner enforced) are the secure defaults and should stay on.
- S3 is also the standard Terraform remote state backend, with native state locking through `use_lockfile`.
